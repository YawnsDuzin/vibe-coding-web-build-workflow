# Step 13: Vercel 무료 티어 관리

> **이 단계의 목표:** Vercel Hobby(무료) 플랜의 한도를 정확히 파악하고, 한도 내에서 안전하게 운영하며, 초과 시 대응 방안을 정리한다.

---

## 13-1. Vercel Hobby 플랜 한도 상세

### 핵심 한도 (2024년 기준)

| 항목 | 무료 한도 | 초과 시 |
|------|:---------:|---------|
| **대역폭** | 100GB/월 | 사이트 일시 중단 (다음 달 초기화) |
| **서버리스 함수 실행** | 100GB-hours/월 | 함수 실행 중단 |
| **빌드 실행 시간** | 6,000분/월 | 빌드 큐 대기 또는 실패 |
| **이미지 최적화** | 1,000건/월 | 원본 이미지로 대체 제공 |
| **동시 빌드** | 1개 | 큐에서 순서 대기 |
| **프로젝트 수** | 200개 | 추가 프로젝트 생성 불가 |
| **팀원** | 1명 (Hobby) | 개인 계정만 |
| **커스텀 도메인** | 50개/프로젝트 | 추가 불가 |
| **환경변수** | 프로젝트당 100개 | 추가 불가 |

### 서버리스 함수 한도 상세

| 항목 | Hobby |
|------|:-----:|
| 실행 시간 제한 | 요청당 최대 10초 |
| 메모리 | 1,024MB |
| 번들 크기 | 50MB (압축 후) |
| 동시 실행 | 제한 있음 (명시되지 않음) |

### 회사 홈페이지에서의 실제 사용량 추정

| 항목 | 추정 사용량 | 무료 한도 대비 |
|------|:---------:|:------------:|
| 대역폭 | ~5GB/월 (일 방문 500명 기준) | 5% |
| 서버리스 | ~1GB-hr/월 (문의 폼 처리) | 1% |
| 빌드 시간 | ~300분/월 (일 5회 배포 기준) | 5% |
| 이미지 최적화 | ~200건/월 | 20% |

> 회사 소개 사이트 규모에서는 무료 한도의 **5~20%** 정도만 사용하므로 여유가 충분하다.

## 13-2. 사용량 확인 방법

### Vercel 대시보드에서 확인

```
① Vercel 대시보드 접속 → 프로젝트 선택

② Usage 탭 클릭
   → 대역폭: Bandwidth 그래프
   → 서버리스: Serverless Function Execution 그래프
   → 빌드: Build Execution 그래프
   → 이미지: Image Optimization 그래프

③ 월별/일별 추이 확인 가능
```

### 확인 주기 권장

| 항목 | 확인 주기 | 경고 기준 |
|------|:---------:|:---------:|
| 대역폭 | 월 1회 | 60GB 이상 (60%) |
| 서버리스 | 월 1회 | 50GB-hr 이상 (50%) |
| 빌드 시간 | 월 1회 | 4,000분 이상 (67%) |
| 이미지 최적화 | 월 1회 | 700건 이상 (70%) |

## 13-3. 사용량 절약 팁

### 대역폭 절약

```
1. 이미지 최적화
   - next/image 사용 (자동 WebP 변환, 리사이징)
   - 대형 이미지는 사전 압축 후 업로드
   - 적절한 width/height 지정으로 과도한 크기 방지

2. 정적 자산 캐싱
   - Next.js가 자동으로 적절한 Cache-Control 헤더 설정
   - public/ 폴더의 파일은 immutable 캐싱

3. 불필요한 자산 제거
   - 사용하지 않는 이미지, 폰트 삭제
   - 폰트 서브셋 적용 (한글 전체 → 자주 쓰는 글자만)
```

### 빌드 시간 절약

```
1. CI에서 불필요한 빌드 방지
   - paths-ignore로 문서 변경 시 빌드 스킵 (이미 적용됨)
   - 캐싱 활성화 (pnpm cache, Next.js cache)

2. 빌드 최적화
   - next.config.ts에서 불필요한 페이지 제외
   - 이미지 최적화를 빌드 타임이 아닌 온디맨드로

3. 배포 빈도 조절
   - main 브랜치에만 배포 (feature 브랜치는 프리뷰만)
   - 콘텐츠 변경은 모아서 한 번에 머지
```

### 서버리스 함수 절약

```
1. 정적 생성 최대 활용
   - generateStaticParams로 빌드 시 정적 페이지 생성
   - ISR(Incremental Static Regeneration)으로 재빌드 주기 조절

2. 문의 폼 최적화
   - rate limiting 적용 (같은 IP에서 분당 5회 제한)
   - 봇 방지: honeypot 필드 또는 간단한 퀴즈
```

## 13-4. 한도 초과 시 대응 방안

### 즉시 대응

| 상황 | 증상 | 대응 |
|------|------|------|
| 대역폭 초과 | 사이트 접속 시 Vercel 한도 페이지 표시 | 다음 달 1일에 자동 초기화. 긴급 시 Pro 업그레이드 |
| 빌드 시간 초과 | 배포가 큐에서 대기하거나 실패 | 불필요한 배포 줄이기. 긴급 시 Vercel CLI 로컬 빌드 후 수동 배포 |
| 서버리스 초과 | 문의 폼 등 동적 기능 중단 | 서버리스 사용량 최적화 또는 Pro 업그레이드 |

### 장기 대응: Pro 플랜 전환 시점

아래 상황이 발생하면 Pro 플랜($20/월)을 검토한다.

```
□ 대역폭이 매월 80GB 이상 → 트래픽 성장
□ 팀원이 2명 이상 필요 → 협업 필요
□ 상업용 사이트 운영 → Hobby 약관상 비상업적 사용 권장
□ SLA(가동 보장)가 필요 → 비즈니스 크리티컬 사이트
□ 고급 기능 필요 → 팀 권한 관리, 방화벽, DDoS 보호 등
```

### Pro vs Hobby 비교

| 항목 | Hobby (무료) | Pro ($20/월/멤버) |
|------|:----------:|:----------------:|
| 대역폭 | 100GB | 1TB (+$40/100GB) |
| 빌드 시간 | 6,000분 | 24,000분 |
| 서버리스 | 100GB-hr | 1,000GB-hr |
| 이미지 최적화 | 1,000건 | 5,000건 |
| 동시 빌드 | 1 | 3 |
| 팀원 | 1명 | 무제한 |
| 상업적 사용 | ❌ (권장하지 않음) | ✅ |
| SLA | ❌ | ✅ (99.99%) |

## 13-5. Hobby 플랜 약관 주의사항

### 상업적 사용에 대하여

```
Vercel Hobby 플랜 약관 요약:
- Hobby는 "개인적, 비상업적 프로젝트"를 위한 플랜
- 회사 공식 홈페이지는 상업적 용도로 해석될 수 있음
- 초기 개발/테스트 단계에서는 Hobby로 충분
- 프로덕션 공개 후에는 Pro 플랜으로 전환을 권장
```

### 권장 운영 전략

```
[개발 단계] Hobby 플랜으로 시작
  → 무료로 개발, 테스트, 프리뷰 배포
  → 모든 기능 구현 및 검증 완료
           ↓
[소프트 런칭] Hobby로 유지
  → 사내 공유, 소규모 외부 테스트
  → 트래픽 패턴 및 사용량 모니터링
           ↓
[정식 오픈] Pro 플랜 전환 ($20/월)
  → 외부 공개, 마케팅 시작
  → 상업적 사용 약관 준수
  → SLA 보장, 팀 협업 기능 활용
```

## 13-6. 대안 호스팅 (무료 지속이 필수인 경우)

Hobby 약관이 걸리거나 Pro 비용이 부담되는 경우의 대안:

### Cloudflare Pages

```bash
# Next.js 프로젝트를 Cloudflare Pages에 배포하는 방법

# 1. 어댑터 설치
pnpm add @cloudflare/next-on-pages

# 2. 빌드 명령어 변경
# package.json:
#   "build": "npx @cloudflare/next-on-pages"

# 3. Cloudflare 대시보드에서 Pages 프로젝트 생성
# GitHub 저장소 연결 → 자동 배포
```

| 항목 | Cloudflare Pages (무료) |
|------|:---------------------:|
| 대역폭 | **무제한** |
| 빌드 | 500회/월 |
| 요청 | 100,000/일 |
| 상업적 사용 | **✅ 허용** |

> 대역폭 무제한 + 상업적 사용 허용이라 무료 지속 운영에 가장 유리하다. 단, Next.js 일부 기능 호환성 확인이 필요하다.

## 13-7. 모니터링 자동화 프롬프트

```
Vercel 사용량을 모니터링하는 간단한 스크립트를 만들어줘:

1. Vercel API로 현재 월 사용량 조회
   - GET /v1/usage → bandwidth, serverlessFunctionExecution 등
2. 각 항목이 무료 한도의 70%를 넘으면 경고 출력
3. GitHub Actions cron으로 매주 월요일 실행
4. 경고 시 Slack 웹훅으로 알림 발송
```

> 이 프롬프트를 Claude Code에 전달하면 자동 모니터링 스크립트를 생성해준다.
