# Step 6: 비개발자 콘텐츠 편집 가이드

> **이 단계의 목표:** 개발 지식이 없는 마케팅/HR 담당자가 GitHub 웹 UI에서 직접 콘텐츠를 수정하고 배포할 수 있도록 안내한다.

---

## 6-1. 이 가이드의 대상

| 대상 | 역할 | 편집 범위 |
|------|------|----------|
| 마케팅 담당자 | 솔루션 설명, 회사 소개 텍스트 수정 | `content/solutions/*.mdx` |
| HR 담당자 | 채용 공고 추가/수정/마감 | `content/careers/*.mdx` |
| 경영진 | 회사 비전/미션 텍스트 검토·수정 | `content/solutions/*.mdx`, `content/careers/*.mdx` |

**필요한 것:** GitHub 계정 + 웹 브라우저 (별도 소프트웨어 설치 불필요)

---

## 6-2. 사전 준비

### GitHub 계정 생성 및 초대

```
1. https://github.com 접속 → "Sign up" 클릭
2. 이메일, 비밀번호, 사용자명 입력 후 계정 생성
3. 개발자에게 GitHub 사용자명 전달
4. 개발자가 저장소에 Collaborator로 초대
5. 이메일에서 초대 수락 링크 클릭
```

### 저장소 접근 확인

```
1. https://github.com/your-org/company-homepage 접속
2. content/ 폴더가 보이면 정상
3. content/solutions/ 또는 content/careers/ 폴더 진입
```

---

## 6-3. MDX 파일 구조 이해하기

MDX 파일은 **두 부분**으로 구성된다.

```markdown
---
title: "클라우드 매니저"          ← ① frontmatter (메타 정보)
description: "클라우드 인프라 통합 관리 솔루션"
icon: "cloud"
features:
  - "멀티 클라우드 통합 관리"
  - "실시간 비용 모니터링"
  - "자동 스케일링"
order: 1
---

여기서부터가 본문입니다.          ← ② 본문 (마크다운 형식)

## 주요 특징

클라우드 매니저는 AWS, GCP, Azure를
하나의 대시보드에서 관리할 수 있습니다.
```

### frontmatter 영역 (`---` 사이)

| 필드 | 의미 | 작성 규칙 |
|------|------|----------|
| `title` | 제목 (페이지에 표시) | 큰따옴표(`"..."`)로 감싸기 |
| `description` | 한 줄 설명 | 큰따옴표로 감싸기, 50자 이내 권장 |
| `icon` | 아이콘 이름 | 개발자에게 사용 가능한 아이콘 목록 확인 |
| `features` | 기능 목록 | `- "항목"` 형식으로 줄마다 하나씩 |
| `order` | 표시 순서 | 숫자 (1이 가장 먼저) |

### 본문 영역 (마크다운 문법)

| 문법 | 결과 | 예시 |
|------|------|------|
| `# 제목` | 큰 제목 (H1) | `# 주요 특징` |
| `## 소제목` | 중간 제목 (H2) | `## 상세 기능` |
| `**굵게**` | **굵게** | `**중요한 내용**` |
| `*기울임*` | *기울임* | `*참고 사항*` |
| `- 항목` | 글머리 기호 목록 | `- 첫 번째 항목` |
| `1. 항목` | 번호 목록 | `1. 첫 번째 단계` |
| `[텍스트](URL)` | 링크 | `[자세히 보기](/contact)` |
| `![설명](경로)` | 이미지 | `![제품 화면](/images/solutions/product-a.png)` |

## 6-4. 기존 콘텐츠 수정하기

### 단계별 절차

```
① GitHub 저장소 접속
   → https://github.com/your-org/company-homepage

② 수정할 파일 찾기
   → content/ 폴더 클릭
   → solutions/ 또는 careers/ 폴더 클릭
   → 수정할 .mdx 파일 클릭

③ 편집 모드 진입
   → 파일 내용 위의 연필 아이콘 (✏️) 클릭
   → 또는 키보드 단축키 'E' 누르기

④ 내용 수정
   → frontmatter: 따옴표 안의 텍스트만 수정
   → 본문: 마크다운 형식으로 자유롭게 편집
   → "Preview" 탭으로 변경 결과 미리보기

⑤ 변경사항 저장 (커밋)
   → 페이지 하단의 "Commit changes..." 버튼 클릭
   → "Create a new branch for this commit and start a pull request" 선택
   → 브랜치 이름 예시: update-solution-cloud-manager
   → "Propose changes" 클릭

⑥ Pull Request 생성
   → 제목 예시: "클라우드 매니저 설명 업데이트"
   → "Create pull request" 클릭

⑦ 프리뷰 확인
   → PR 페이지에서 Vercel이 자동으로 댓글로 프리뷰 URL을 남김
   → 프리뷰 URL 클릭하여 실제 사이트에서 변경 내용 확인

⑧ 승인 대기
   → 개발자가 PR을 검토하고 승인 (Approve)
   → 머지(Merge)되면 프로덕션에 자동 배포
```

### 수정 시 주의사항

```
✅ 해도 되는 것:
   - 따옴표 안의 텍스트 변경
   - 본문 마크다운 수정
   - features 목록 항목 추가/삭제/수정
   - order 숫자 변경

❌ 하면 안 되는 것:
   - frontmatter의 필드 이름 변경 (title → name 등)
   - --- 구분선 삭제
   - 파일 확장자(.mdx) 변경
   - 따옴표 짝이 안 맞게 수정 ("텍스트 ← 닫는 따옴표 누락)
```

## 6-5. 새 콘텐츠 추가하기

### 새 솔루션 추가

```
① GitHub 저장소에서 content/solutions/ 폴더 접속

② "Add file" 버튼 → "Create new file" 클릭

③ 파일 이름 입력
   → 영문 소문자, 하이픈 사용: new-product.mdx
   → 예시: data-analytics.mdx

④ 아래 템플릿을 복사하여 붙여넣기:
```

```markdown
---
title: "제품명을 여기에"
description: "제품 한 줄 설명을 여기에"
icon: "chart"
features:
  - "기능 1"
  - "기능 2"
  - "기능 3"
order: 5
---

## 개요

제품에 대한 전체적인 설명을 여기에 작성합니다.

## 주요 기능

상세한 기능 설명을 작성합니다.

## 도입 효과

이 제품을 도입하면 어떤 효과가 있는지 작성합니다.
```

```
⑤ "Create a new branch..." 선택 후 PR 생성
   → 이하 절차는 수정 시와 동일
```

### 새 채용 공고 추가

```
① content/careers/ 폴더에서 "Create new file"

② 파일 이름: 포지션-영문명.mdx
   → 예시: product-designer.mdx

③ 아래 템플릿 복사 후 내용 작성:
```

```markdown
---
title: "포지션명"
team: "소속 팀명"
location: "서울"
type: "정규직"
isOpen: true
---

## 주요 업무

- 업무 내용 1
- 업무 내용 2
- 업무 내용 3

## 자격 요건

- 필수 자격 1
- 필수 자격 2

## 우대 사항

- 우대 사항 1
- 우대 사항 2

## 혜택 및 복지

- 복지 1
- 복지 2
```

### 채용 공고 마감

```
해당 MDX 파일의 frontmatter에서:
  isOpen: true  →  isOpen: false  로 변경
```

## 6-6. 이미지 추가/변경하기

### 이미지 업로드

```
① GitHub 저장소에서 public/images/ 폴더 접속
   → 해당 카테고리 폴더 (solutions/, team/ 등) 진입

② "Add file" → "Upload files" 클릭

③ 이미지 파일을 드래그 앤 드롭 또는 선택

④ "Create a new branch..." 선택 후 PR 생성
```

### 이미지 규격 권장사항

| 용도 | 권장 크기 | 파일 형식 | 파일명 규칙 |
|------|----------|----------|------------|
| 솔루션 대표 이미지 | 800x600px | PNG, WebP | `product-name.png` |
| 팀원 프로필 사진 | 400x400px (정사각형) | PNG, JPG | `firstname-lastname.jpg` |
| OG 이미지 | 1200x630px | PNG | `og-image.png` |
| 히어로 배경 | 1920x1080px | WebP | `hero-bg.webp` |

### MDX에서 이미지 사용하기

```markdown
<!-- 업로드한 이미지를 본문에서 사용할 때 -->
![제품 대시보드 화면](/images/solutions/cloud-manager-dashboard.png)
```

## 6-7. 자주 묻는 질문 (FAQ)

### Q: 수정한 내용이 바로 반영되나요?

**A:** 아닙니다. PR을 생성하면 먼저 프리뷰 URL에서 확인할 수 있고, 개발자가 승인(Merge)한 후 프로덕션에 반영됩니다. 보통 승인 후 2~3분 내에 반영됩니다.

### Q: 실수로 잘못 수정했어요. 되돌릴 수 있나요?

**A:** PR이 아직 머지되지 않았다면, PR 페이지에서 "Close pull request"를 클릭하면 됩니다. 이미 머지된 경우 개발자에게 요청하세요.

### Q: frontmatter 형식을 틀려서 빌드가 실패했어요.

**A:** PR의 Checks 탭에서 빌드 실패 여부를 확인할 수 있습니다. 실패한 경우 PR 페이지에서 해당 파일을 다시 편집하여 수정하면 됩니다. 흔한 실수:
- 따옴표(`"`) 짝이 안 맞음
- `---` 구분선이 빠짐
- 들여쓰기가 잘못됨 (features 목록에서 스페이스 2칸)

### Q: 여러 파일을 한 번에 수정해야 해요.

**A:** 첫 번째 파일 수정 시 브랜치를 만들고, 같은 브랜치에서 나머지 파일도 수정하면 하나의 PR에 모든 변경사항이 포함됩니다. 파일 편집 후 커밋 시 기존 브랜치를 선택하면 됩니다.

### Q: 이미지가 너무 커서 업로드가 안 돼요.

**A:** GitHub은 파일당 25MB 제한이 있습니다. 이미지를 압축하거나(TinyPNG 등), 개발자에게 이미지 최적화를 요청하세요.
