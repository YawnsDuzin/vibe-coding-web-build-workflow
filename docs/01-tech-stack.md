## 1-2. 프레임워크 비교

### 후보 상세 분석

| 항목 | Next.js 14+ (App Router) | Astro 4+ | Gatsby 5 |
|------|:-:|:-:|:-:|
| 바이브코딩 친화성 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 무료 호스팅 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 비개발자 수정 | ⭐⭐ | ⭐⭐ | ⭐⭐ |
| 초기 개발 속도 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 커뮤니티/문서 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |

### 각 후보 장단점

**Next.js 14+ (App Router)**
- 장점: React 생태계 최대 프레임워크. Claude Code의 학습 데이터에 가장 많이 포함되어 있어 코드 생성 정확도가 높다. Vercel과 네이티브 통합으로 배포가 즉각적이다. Server Components, Server Actions 등 최신 React 패턴 지원.
- 단점: 정적 사이트 전용이 아니라 번들 크기가 상대적으로 클 수 있다. App Router의 학습 곡선이 존재하지만, AI가 대부분 처리하므로 바이브코딩에서는 문제가 되지 않는다.

**Astro 4+**
- 장점: 정적 사이트에 최적화된 프레임워크. 제로 JS 기본 정책으로 로딩 성능이 매우 우수하다. MDX 네이티브 지원. 다양한 UI 프레임워크(React, Vue, Svelte) 혼용 가능.
- 단점: Next.js 대비 생태계가 작고, Claude Code의 Astro 관련 학습 데이터가 상대적으로 적다. 동적 기능(문의 폼 처리 등) 추가 시 별도 설정이 필요하다.

**Gatsby 5**
- 장점: GraphQL 기반 데이터 레이어가 강력하다. 풍부한 플러그인 생태계.
- 단점: 개발 속도가 느리고 빌드 시간이 길다. GraphQL 의존성이 바이브코딩 시 불필요한 복잡성을 추가한다. 커뮤니티 활성도가 하락 추세.

### ✅ 최종 선정: Next.js 14+ (App Router)

> Claude Code가 가장 정확하게 코드를 생성하는 React 기반 프레임워크이다.
> 파일 기반 라우팅(`app/` 디렉토리)은 AI가 페이지 구조를 예측하고 올바른 위치에 파일을 생성하기 쉽게 만든다.
> Vercel 무료 호스팅과의 zero-config 통합은 배포 파이프라인 설정을 최소화한다.

## 1-3. 스타일링 비교

### 후보 상세 분석

| 항목 | Tailwind CSS v4 | CSS Modules | styled-components |
|------|:-:|:-:|:-:|
| 바이브코딩 친화성 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |
| 번들 크기 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 커스터마이징 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| 커뮤니티/문서 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |

### 각 후보 장단점

**Tailwind CSS v4**
- 장점: 유틸리티 클래스를 JSX 안에 직접 작성하므로 AI가 **별도 CSS 파일 없이** 한 파일 안에서 레이아웃+스타일을 동시에 생성한다. 프롬프트 한 번으로 완성된 UI를 받을 수 있어 바이브코딩 효율이 가장 높다. v4부터 설정 파일 없이 CSS 기반 설정이 가능해져 초기 세팅이 더 간편해졌다.
- 단점: 클래스명이 길어져 JSX 가독성이 떨어질 수 있다. 하지만 AI가 코드를 생성하는 바이브코딩에서는 가독성보다 생성 효율이 더 중요하다.

**CSS Modules**
- 장점: 스코프가 자동으로 격리되어 스타일 충돌이 없다. 순수 CSS라 별도 의존성이 필요 없다.
- 단점: AI가 `.tsx` 파일과 `.module.css` 파일을 동시에 생성/동기화해야 해서 바이브코딩 시 오류 가능성이 높다. 클래스명을 별도로 정의해야 하므로 프롬프트가 길어진다.

**styled-components**
- 장점: CSS-in-JS로 컴포넌트와 스타일이 한 파일에 공존. 동적 스타일링이 용이하다.
- 단점: 런타임 CSS 생성으로 번들 크기 증가. Next.js App Router와의 SSR 호환에 추가 설정 필요. 바이브코딩 시 템플릿 리터럴 안의 CSS와 JSX를 동시에 다루는 복잡성이 있다.

### ✅ 최종 선정: Tailwind CSS v4

> AI가 JSX와 스타일을 한 파일에서 동시 생성하므로, 프롬프트 한 번에 완성된 UI를 받을 수 있다.
> 유틸리티 클래스 기반이라 디자인 시스템 없이도 일관된 스타일을 유지하기 쉽다.

## 1-4. 콘텐츠 관리(CMS) 비교

### 후보 상세 분석

| 항목 | MDX 파일 기반 | Contentlayer + MD | Sanity CMS |
|------|:-:|:-:|:-:|
| 비개발자 편집 | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| 무료 티어 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 바이브코딩 통합 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |
| 커뮤니티/문서 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ |

### 각 후보 장단점

**MDX 파일 기반 (content/ 디렉토리)**
- 장점: 외부 서비스 의존 없이 Git 저장소 내 `.mdx` 파일만 수정하면 콘텐츠가 변경된다. Claude Code가 콘텐츠 파일을 직접 생성/수정할 수 있어 바이브코딩과 완벽하게 호환된다. 비개발자도 GitHub 웹 UI에서 마크다운 텍스트를 편집하고 PR을 생성할 수 있다.
- 단점: GitHub UI에 익숙하지 않은 비개발자에게 진입 장벽이 있다. 이미지 업로드가 Git 기반이라 대용량 미디어 관리에는 부적합하다.
- **보완 방법:** 비개발자용 콘텐츠 편집 가이드 문서를 별도 제공하거나, 이미지는 외부 CDN(Cloudinary 무료 티어)을 활용한다.

**Contentlayer + Markdown**
- 장점: 타입 안전한 콘텐츠 스키마를 정의할 수 있다. 빌드 시 콘텐츠를 TypeScript 객체로 변환.
- 단점: Contentlayer 프로젝트의 유지보수가 불확실한 상태(2024년 기준). Next.js 14+ App Router와의 호환성 이슈가 보고되고 있다.

**Sanity CMS**
- 장점: 직관적인 관리 패널(Sanity Studio)로 비개발자도 쉽게 콘텐츠를 편집할 수 있다. 실시간 미리보기 지원. 이미지 CDN 내장.
- 단점: 무료 티어에 API 호출 제한(월 100K 요청)이 있다. 외부 서비스 의존성이 추가된다. 바이브코딩 시 Sanity 스키마와 GROQ 쿼리를 동시에 관리해야 하는 복잡성이 있다.

### ✅ 최종 선정: MDX 파일 기반 (content/ 디렉토리)

> 외부 서비스 의존 없이 Git 저장소 안에서 모든 콘텐츠를 관리한다.
> Claude Code가 `.mdx` 파일을 직접 생성/수정할 수 있어 바이브코딩 흐름이 끊기지 않는다.
> 비개발자는 GitHub 웹 UI에서 마크다운을 편집하고, PR 머지 시 자동 배포된다.

## 1-5. 호스팅 비교

### 후보 상세 분석

| 항목 | Vercel (Hobby) | Cloudflare Pages | Netlify (Starter) |
|------|:-:|:-:|:-:|
| 무료 티어 범위 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| Next.js 지원 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |
| 배포 편의성 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| 커뮤니티/문서 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |

### 무료 티어 상세 비교

| 항목 | Vercel Hobby | Cloudflare Pages | Netlify Starter |
|------|-------------|-----------------|----------------|
| 대역폭 | 100GB/월 | 무제한 | 100GB/월 |
| 빌드 시간 | 6,000분/월 | 500회/월 | 300분/월 |
| 서버리스 함수 | ✅ (100GB-hrs) | ✅ (Workers) | ✅ (125K 요청) |
| 프리뷰 배포 | ✅ (PR마다 자동) | ✅ | ✅ |
| 커스텀 도메인 | ✅ | ✅ | ✅ |
| HTTPS | ✅ (자동) | ✅ (자동) | ✅ (자동) |
| Edge 함수 | ✅ | ✅ | ✅ |

### 각 후보 장단점

**Vercel (Hobby)**
- 장점: Next.js 제작사의 호스팅이라 **zero-config 배포**가 가능하다. Git push만으로 프리뷰/프로덕션 배포가 자동 완료. ISR(Incremental Static Regeneration), Server Components 등 Next.js 최신 기능을 100% 지원한다.
- 단점: 상업용 사이트는 유료 플랜(Pro $20/월) 권장. Hobby 플랜은 비상업적 개인 프로젝트용. 단, 초기 구축 및 테스트 단계에서는 Hobby로 충분하다.

**Cloudflare Pages**
- 장점: 무제한 대역폭이 가장 큰 장점. 글로벌 CDN 성능이 뛰어나다. Workers와 연동 시 서버리스 기능도 강력하다.
- 단점: Next.js의 일부 기능(ISR, Middleware 일부)이 완전히 호환되지 않을 수 있다. `@cloudflare/next-on-pages` 어댑터가 필요하며, 설정 복잡도가 올라간다.

**Netlify (Starter)**
- 장점: 직관적인 UI와 간편한 배포 설정. 폼 처리 기능 내장(월 100건 무료).
- 단점: 빌드 시간 제한(300분/월)이 타이트하다. Next.js 지원이 Vercel 대비 뒤처지며, 일부 기능에서 호환성 문제가 발생할 수 있다.

### ✅ 최종 선정: Vercel (Hobby 플랜)

> Next.js 제작사의 호스팅으로 별도 설정 없이 `git push`만으로 배포가 완료된다.
> PR마다 프리뷰 URL이 자동 생성되어 비개발자도 변경사항을 미리 확인할 수 있다.

## 1-6. 패키지 매니저 비교

### 후보 상세 분석

| 항목 | pnpm 9 | npm 10 | yarn 4 (Berry) |
|------|:-:|:-:|:-:|
| 설치 속도 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ |
| 디스크 효율 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐ |
| 바이브코딩 친화성 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 안정성 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |

### 각 후보 장단점

**pnpm 9**
- 장점: 심링크 기반 node_modules로 디스크 공간을 최대 50% 절약. 설치 속도가 npm 대비 2~3배 빠르다. `pnpm` 명령어 체계가 npm과 거의 동일해서 Claude Code가 정확하게 명령어를 생성한다. GitHub Actions에서 공식 `pnpm/action-setup` 액션을 지원한다.
- 단점: npm 대비 인지도가 낮아 일부 개발자에게 생소할 수 있다.

**npm 10**
- 장점: Node.js에 기본 내장. 추가 설치 불필요. 가장 범용적이라 AI가 npm 명령어를 정확하게 생성한다.
- 단점: 설치 속도가 느리고 디스크 효율이 좋지 않다. `node_modules` 중복 설치 문제.

**yarn 4 (Berry)**
- 장점: Plug'n'Play(PnP) 모드로 `node_modules` 없이 동작 가능. 우수한 워크스페이스 지원.
- 단점: PnP 모드에서 일부 패키지 호환성 문제 발생. `.yarnrc.yml` 설정 필요. AI가 yarn Berry의 특수한 명령어/설정을 잘못 생성할 확률이 npm/pnpm 대비 높다.

### ✅ 최종 선정: pnpm 9

> npm과 동일한 명령어 체계로 AI 호환성이 높으면서, 설치 속도와 디스크 효율까지 우수하다.
> CI 환경에서도 캐싱 효과가 뛰어나 빌드 시간을 단축시킨다.

## 1-7. 최종 기술스택 요약

```
┌─────────────────────────────────────────────────┐
│  Framework:  Next.js 14+ (App Router)           │
│  Styling:    Tailwind CSS v4                    │
│  Content:    MDX (content/ 디렉토리)              │
│  Hosting:    Vercel (Hobby)                     │
│  Package:    pnpm 9                             │
│  Language:   TypeScript                         │
│  Lint:       ESLint (Next.js 기본 설정)           │
└─────────────────────────────────────────────────┘
```

### 기술스택 간 시너지

```
pnpm create next-app → Tailwind CSS 자동 포함 → TypeScript 자동 포함
     ↓
content/*.mdx → next-mdx-remote로 파싱 → App Router 페이지에서 렌더링
     ↓
git push → Vercel 자동 빌드/배포 → 프리뷰 URL 생성
```

> **다음 단계:** [Step 2: 프로젝트 초기 세팅](./02-project-setup.md)에서 이 기술스택을 기반으로 실제 프로젝트를 생성한다.
